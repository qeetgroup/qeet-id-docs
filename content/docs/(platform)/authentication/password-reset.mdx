---
title: Password reset
description: How a forgotten password is replaced — the request, the emailed link, its lifetime and single use, the password rules, and what happens to existing sessions.
---

A password reset lets someone who has forgotten their password choose a new one through a link
emailed to the account's address. It is the recovery path for password accounts; accounts that
sign in with a [passkey](/docs/authentication/passkeys) or a
[magic link](/docs/authentication/magic-links) do not need it.

## Where it is available

| Surface | What it offers |
| --- | --- |
| [Hosted login](/docs/authentication/hosted-login) | **Forgot password?** on the sign-in page opens **Reset your password**; the emailed link opens hosted login's **Choose a new password** page, and a journey that started at an application's sign-in continues there afterwards. |
| Qeet ID console | **Forgot password?** on the console's sign-in page; the emailed link opens the console's reset screen. |
| HTTP API | Two endpoints — request and confirm — described below. |
| React SDK | `forgotPassword` and `resetPassword` call the same endpoints, but `forgotPassword` does not say it comes from hosted login, so its emailed links open the **console's** reset screen. To keep users in hosted login, send them to its **Forgot password?** page. |

## How a reset works

<Steps>

<Step>

**Request a link.** The user enters their email address. The answer is the same whether or not
the address belongs to an account.

</Step>

<Step>

**Qeet ID emails the link** — subject "Reset your password" — if the address belongs to an account
that has not been deleted. The link opens where the reset was asked for: hosted login's `/reset`
page, or the console's reset screen.

</Step>

<Step>

**The user chooses a new password.** The page sends it with the link's token. The password must
pass the rules of the user's organization; if it does not, nothing changes and the same link can
be used again.

</Step>

<Step>

**Every Qeet ID session of the account ends**, and the user signs in again with the new password.

</Step>

</Steps>

### Request a link

```http title="Request"
POST /v1/auth/forgot-password
Content-Type: application/json

{
  "email": "ada@example.com",
  "app": "hosted_login",
  "return_to": "https://api.id.qeet.in/oauth/authorize?client_id=…"
}
```

<TypeTable
  type={{
    email: {
      description: "The account's address. The look-up is platform-wide — an email address belongs to one account across all organizations.",
      type: "string",
      required: true,
    },
    app: {
      description: "\"hosted_login\" makes the emailed link open hosted login's reset page. Anything else, or nothing, makes it open the console's.",
      type: "string",
    },
    return_to: {
      description: "Hosted login only: where to continue after the reset. Kept only when it is this Qeet ID's own /oauth/authorize URL; anything else is dropped.",
      type: "string (URL)",
    },
    tenant_id: {
      description: "Accepted for compatibility and not used: the address alone identifies the account.",
      type: "string (UUID)",
    },
  }}
/>

```json title="Response — 200, whatever the address"
{ "message": "If an account exists for that email, we've sent a password reset link." }
```

<Callout type="info" title="Local development">
  When the server runs with `SERVICE_ENV=dev`, the response also carries `dev_reset_token`, so the
  flow can be finished without an email provider. No other environment returns it.
</Callout>

### Set the new password

```http title="Request"
POST /v1/auth/reset-password
Content-Type: application/json

{ "token": "…", "new_password": "a long and unique passphrase" }
```

```json title="Response — 200"
{ "message": "Your password has been reset. You can now sign in with your new password." }
```

The new password is checked against the **password rules of the organization the account belongs
to** — its minimum length and character requirements, set under **Authentication → Sign-in →
Password** — or the platform baseline for an account with no organization, plus the breached-password
check where it is turned on. A refused password is answered with the rule it broke —
`authpolicy.password_too_short`, `authpolicy.password_no_uppercase`, `authpolicy.password_no_number`,
`authpolicy.password_no_symbol` or `authpolicy.password_breached` (422) — and leaves both the old
password and the link untouched.

## Lifetime, single use and refusals

A reset link is valid for **one hour** and works **once**. Qeet ID stores only a hash of its token.
Asking again sends a new link; it does not cancel links sent earlier, each of which keeps working
until it is used or expires.

| Situation | Answer |
| --- | --- |
| Unknown token | `recovery.reset_link_invalid` (400) |
| The link was already used | `recovery.link_used` (400) |
| The link has expired | `recovery.link_expired` (400) |
| The new password breaks a rule | `authpolicy.password_*` (422) |

## What a reset does to existing sign-ins

Completing a reset **ends every Qeet ID session of the account** — in the console and in every
application that signed the user in through the Qeet ID API — in the same step that sets the
password, and records
`auth.password_reset_confirmed` in the audit log. From then on:

- **No ended session can be renewed.** Its refresh token is refused, so a device that is signed in
  elsewhere has to sign in again.
- **An access token already issued keeps working until it expires** — at most the access-token
  lifetime, ten minutes by default — because services verify access tokens on their own, without
  asking Qeet ID. Applications subscribed to the `session.revoked` webhook are told at once, with
  reason `password_reset`, and can cut access off sooner. See
  [Manage sessions](/docs/authentication/sessions#what-ending-a-session-does).

<Callout type="warn" title="What a reset does not end">
  A reset ends Qeet ID sessions only. It does not end a **hosted-login sign-in** that is still open
  in a browser (it lasts 30 minutes at most), **sign-ins applications obtained through OAuth**, or
  **[trusted devices](/docs/authentication/trusted-devices)**. If the reset follows a suspected
  account compromise, also use **Sign out everywhere** (**Account → Sessions** in the console, or
  [the API](/docs/authentication/sessions#sign-out-everywhere)), which ends all of them.
</Callout>
