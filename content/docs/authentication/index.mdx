Authentication is how a user proves their identity. Qeet ID is
**passkeys-first** — WebAuthn is a primary credential, not a bolt-on — and ships
the full range of factors and federation protocols enterprises expect, none of
them behind a paywall.

## Passwords, when you use them

Passwords are optional — a passkey alone can create and access an account. When a
password _is_ used, it's hashed with **Argon2id** (OWASP baseline parameters),
with per-account lockout and an optional [Have I Been Pwned](https://haveibeenpwned.com)
breach check. Legacy bcrypt hashes are verified and transparently upgraded on
next login.

<Callout type="warn">
  Never handle raw credentials yourself. Use the SDKs or hosted login — Qeet ID
  owns hashing, lockout, MFA and risk evaluation so you don't have to.
</Callout>

## Hosted vs. embedded

You can send users to a [hosted login](/docs/authentication/hosted-login) page
(fastest, fully managed and themeable) or **embed** the flow in your own UI with
the SDKs. Both use the same endpoints, so you can start hosted and move in-app
later without changing your backend.
