`@qeet-id/node` is the server-side client for Node and TypeScript runtimes. It
exposes typed resources and verifies sessions locally.

<Callout type="warn" title="Source preview">
  `@qeet-id/node` is not published to npm yet. The examples below document the
  intended `0.1` surface for review against the
  [source repository](https://github.com/qeetgroup/qeet-id-node). Do not add the
  package to a production dependency manifest until a registry release exists.
</Callout>

## Intended initialization

```ts title="lib/qeetid.ts"
import { QeetID } from "@qeet-id/node";

export const qeetid = new QeetID({
  apiKey: process.env.QEETID_API_KEY!,
  baseUrl: process.env.QEETID_BASE_URL,
});
```

## Intended operations

```ts title="server.ts"
// Create a user in a tenant.
const user = await qeetid.users.create({
  tenant_id: tenantId,
  email: "ada@example.com",
});

// Verify a session token (local, cached JWKS).
const claims = await qeetid.sessions.verify(token);

// Check a permission.
const allowed = await qeetid.permissions.check({
  user: claims.userId!,
  tenant: claims.tenantId!,
  permission: "billing:write",
});
```

<Callout type="info">
  The Node client currently leads on a couple of resources (token vault, audit
  anomalies). Treat the source and changelog as the contract until the package
  is published.
</Callout>
