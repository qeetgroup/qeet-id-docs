Qeet ID's first-party SDKs wrap the HTTP API with types, defaults and local session verification.
They are pre-1.0 and release independently of the platform and of each other.

## Choose your SDK

The **SDK menu** at the top of the sidebar sets the SDK for the whole site: shared pages — the
quickstart, the platform guides — show that SDK's code, and an SDK's own pages open from here. Your
choice is remembered. To share a page with an SDK already chosen, add `?sdk=` to its URL, for example
`/docs/getting-started/quickstart?sdk=node`.

When a step has no code for the chosen SDK, the page says why and offers the SDKs that have it.

<Callout type="warn" title="Do not install the npm packages yet">
  `@qeet-id/node` and `@qeet-id/react` are not in the public npm registry, so `npm install` fails.

## Without an SDK

Every SDK is a client of the same API, so any language can integrate today: sign users in with a
certified OpenID Connect library (discovery at `/.well-known/openid-configuration`), verify tokens
against `/.well-known/jwks.json`, and call the management API with a secret `qk_` API key sent as
`Authorization: ApiKey qk_…`. Every endpoint is in the
[API reference](https://api.qeet.in/reference#qeet-id).
