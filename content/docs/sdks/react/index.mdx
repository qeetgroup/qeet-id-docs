`@qeet-id/react` provides a provider, guard components and hooks for building
authenticated React apps. It talks to your own backend routes, which hold the
API key — no secrets ship to the browser.

<Callout type="warn" title="Source preview">
  `@qeet-id/react` is not published to npm yet. The examples below document the
  intended `0.1` surface for review against the
  [source repository](https://github.com/qeetgroup/qeet-id-react). Do not add the
  package to a production dependency manifest until a registry release exists.
</Callout>

## Intended redirect-mode setup

```tsx title="App.tsx"
import { QeetIDProvider, SignedIn, SignedOut, SignInButton } from "@qeet-id/react";

export function App() {
  return (
    <QeetIDProvider
      loginUrl="/api/auth/login"
      logoutUrl="/api/auth/logout"
      signUpUrl="/api/auth/sign-up"
    >
      <SignedIn>
        <Dashboard />
      </SignedIn>
      <SignedOut>
        <SignInButton />
      </SignedOut>
    </QeetIDProvider>
  );
}
```

## Read the current user

```tsx title="Profile.tsx"
import { useUser } from "@qeet-id/react";

export function Profile() {
  const { user } = useUser();
  return <span>{user?.email}</span>;
}
```

<Callout type="info" title="Redirect and embedded modes">
  Omit `apiUrl` when the buttons redirect through your own backend routes. Pass
  `apiUrl="https://api.id.qeet.in"` only when using the embedded components and
  hooks that call the Qeet ID API directly.
</Callout>

<Callout type="info">
  A companion `@qeet-id/nextjs` package for App Router route handlers in redirect
  mode is not released. Implement those backend routes in your application until
  its status changes on the roadmap.
</Callout>
