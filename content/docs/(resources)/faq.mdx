<Accordions>

<Accordion title="How is Qeet ID delivered?">
As a service operated by Qeet Group. Your applications use its API, hosted
sign-in pages and [SDKs](/docs/sdks).
</Accordion>

<Accordion title="Which SDK can I install today?">
The Go module is available from GitHub. The Node and React clients are source
previews and are not present in the public npm registry yet. See
[SDK release status](/docs/sdks).
</Accordion>

<Accordion title="Are organization and tenant different objects?">
No. **Organization** is the SDK-facing product term; **tenant** is the API,
token and storage term for the same isolation boundary. A session token carries
one active organization scope.
</Accordion>

<Accordion title="Which authorization model should I use?">
Start with [RBAC](/docs/authorization/rbac) (roles and permissions). Reach for
[ReBAC](/docs/authorization/rebac) when access depends on a relationship to a
specific object, and [ABAC](/docs/authorization/abac) for contextual policies.
All three are built in and all are explainable.
</Accordion>

<Accordion title="Do I have to store passwords?">
No. A [passkey](/docs/authentication/passkeys) alone can create and access an
account. When passwords are used they're hashed with Argon2id — but passwordless
is a first-class path.
</Accordion>

<Accordion title="Does it use PostgreSQL row-level security?">
Not today. Tenant isolation is enforced in the application layer (per-query
scoping plus a router guard); database-level RLS is a planned defense-in-depth
improvement. See [data isolation](/docs/security/data-isolation).
</Accordion>

<Accordion title="Where is the API reference?">
The generated OpenAPI reference is served separately in Scalar and linked from
the top navigation. This portal owns concepts, architecture, guides and SDK
release status rather than duplicating endpoint schemas.
</Accordion>

<Accordion title="Is Qeet ID production-ready?">
It's in active **developer preview**, not general availability. The roadmap
tracks database RLS hardening, public Node/React releases, an external
penetration test and OpenID conformance. Evaluate accordingly.
</Accordion>

<Accordion title="What compliance claims does Qeet ID make?">
The platform produces internal control evidence, but does not currently claim a
SOC 2 or ISO 27001 attestation, FIPS validation or HIPAA BAA. See the
[current compliance posture](/docs/security/compliance).
</Accordion>

<Accordion title="How does it relate to the other Qeet products?">
Qeet ID is the identity hub of the Qeet Group suite — every product authenticates
through it as an OIDC relying party. It emits events that Qeet Notify delivers and
Qeet Logs analyzes. See [architecture](/docs/architecture).
</Accordion>

</Accordions>
